The one decision everything else hangs off

The brief's hardest line is buried in the technical requirements: “avoid re-asking questions if the user provides info early.” That single sentence rules out a script and forces a slot-filling state machine. Every other choice on this page follows from it.

How it works

Three models in a loop, and one thing that remembers

A voice agent is a listening model, a thinking model, and a speaking model passing a conversation between them fast enough that nobody notices the seams. The interesting part isn't the loop — it's the small box hanging off it that remembers what has already been answered.

Conversation architecture

Six stages, and one of them is a gate

The brief lists “Qualification (The 4 Checkpoints)” and then nests six items beneath it — the last two being the pitch and the call to action. Those aren't checkpoints. I read it as four checkpoints followed by two stages, which preserves both the stated count and the stated flow.

How I thought about it

The sentence that breaks a scripted bot

Real callers don't answer one question at a time. They front-load. A script hears this and then asks, cheerfully, what it was just told — and the call is over, because the person now knows nobody is listening.

What a scripted bot says next “So, is this for self-use or investment?”

Three seconds, and the prospect knows they're talking to a machine that isn't listening. No amount of voice quality recovers from it.

Scope

What I built, and what I deliberately didn't

The brief says outbound. Real outbound calling to Indian mobiles runs through TRAI's DLT framework — entity registration, header and template approval, telecom KYC, DND scrubbing. Days to weeks, almost all of it spent waiting on approvals nobody on this project controls.

What this genuinely costs, stated plainly

A web call doesn't test codec degradation, network jitter, barge-in over a live line, or answering-machine detection. Those are real gaps. What the agent does have is the outbound design throughout — it opens cold, identifies itself unprompted, asks permission before proceeding, handles gatekeepers and voicemail, and honours a do-not-call request instantly and without argument.

The flooring trap

Flow 7 asks what flooring the villas come with. There are no villas — this is a plotted development, land only. Several public listings for this project nonetheless describe vitrified tiles and granite platforms, scraped from an apartment template. An agent that repeats that has just mis-sold a RERA-registered land parcel in one sentence.

Fact discipline

A knowledge base defined by what it forbids

Most knowledge bases list what the bot should say. This one also lists what it must never say, with reasons — because the public data on this project is actively polluted, and this is a RERA-registered development where a misquoted price is the developer's exposure, not just an embarrassment.

The number nobody looks up

Every investor asks the per-square-foot rate inside ninety seconds. The brief never states one — but it's sitting in the price band, and both ends agree.

₹92,40,000 ÷ 1,200 = ₹7,700
₹7,700 × 3,199 = ₹2.46 Cr ✓

Derived rather than looked up, so it can never contradict another number the agent quotes.

One line, fifteen questions

“That's exactly what our Property Expert can confirm precisely — I don't want to give you a number that isn't exact. Shall I have them cover it on the call?”

Booking amount, NRE routing, payment schedule, stamp duty, plot availability. Every knowledge gap converts into the close.

Platform decision

Sarvam for production, ElevenLabs as the control

Four of the brief's requirements — Indic pronunciation, Hinglish, mid-call language switching, outbound — are platform primitives on Sarvam and workarounds on ElevenLabs. When the primitives match the requirements, that's the platform.

Both agents run the identical system prompt, and the same two flows are recorded on each. If ElevenLabs sounds better in English, that goes in the submission — a benchmark that only confirms the decision isn't a benchmark. The likely honest conclusion is Indic-native for Indic, global for English, which is more useful than either platform winning outright.

Not in the brief

The call isn't the output. The lead record is.

A qualification bot exists to feed a pipeline, so every call ends by emitting a structured record rather than just a nice transcript. The temperature scale is Hot / Warm / Lukewarm / Cold — deliberately the same taxonomy Revspot already uses.

Honestly

What this doesn't do yet

  • No live telephony. Untested against codec degradation, jitter and real barge-in.
  • Slot inference is probabilistic. A genuinely ambiguous answer can mis-slot. The prompt constrains what may be inferred and prefers an empty slot to a stretch — that reduces the failure rate, it doesn't remove it.
  • Hindi is verified by ear, not measured. No word-error-rate benchmark against a labelled Hinglish set.
  • Knowledge base is static. Live inventory and phase status would need a CRM tool call.
  • Seven flows is a demonstration, not an evaluation. “It works” is currently a judgment; it should be a number.

What I'd do next, in order

  1. DLT registration and a live number — closes the largest gap.
  2. CRM tool call for live inventory, plus write-back of the qualification record.
  3. An eval set: 30–50 scripted calls with labelled expected slots, scored automatically.
  4. Latency budget measured per stage — ASR, LLM, TTS separately. Perceived naturalness is mostly a latency property, and I haven't measured it.
  5. A/B the opening line. Permission is the highest drop-off moment on any outbound call, and it deserves data rather than taste.
